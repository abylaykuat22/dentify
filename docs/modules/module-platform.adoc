|Description
|Платформа — общее ядро: тенант-контекст, безопасность, аудит, ошибки, i18n, логирование. 
+
Ни от одного модуля не зависит, от неё зависят все. Другим модулям открыты только её named interfaces: `api` — всем, `identity` (клиника в сессии, вход, сессии, лимиты входа, чтение журнала) — только iam. Остальные пакеты — внутренние.
|Base package
|`kz.dentify.platform`
|Spring components
|* `k.d.p.identity.AuditJournal` (via `k.d.p.audit.JdbcAuditJournal` -- Чтение журнала действий клиники контекста (PLT-09). Запрос всегда с `clinic_id` клиники контекста — это и изоляция вместе с RLS, и первая колонка индексов; период отсекает лишние партиции. Лента без фильтра по объекту всегда ограничена периодом: без начала — последние `dentify.audit.default-period` (30 дней), поиск по тексту — не длиннее `dentify.audit.search-max-period` (366 дней): у него нет индекса. Тексты — на языке запроса; ИИН, телефоны и e-mail без права `k.d.p.api.Permissions#PATIENT_PHONES` — маской в имени объекта, аргументах и разнице; IP — маской всегда.)
* `k.d.p.api.AuditService` (via `k.d.p.audit.JdbcAuditService` -- Запись журнала действий в `audit_log` (PLT-09) через JDBC в транзакции, к которой привязан поток: с JPA это то же соединение, что у изменения, и событие фиксируется или откатывается вместе с ним. Клиника — из контекста, RLS не даст записать событие чужой клинике; аккаунт — `k.d.p.api.CurrentAccountProvider`; сотрудник — `k.d.p.api.CurrentStaffProvider`, если его реализует iam; IP — `getRemoteAddr()` HTTP-запроса потока (за прокси — клиент из X-Forwarded-For), вне запроса — пусто. 
+
Время события — часы приложения с точностью до микросекунд (как `timestamptz`), id — `uuidv7()` БД. Для поиска в `search_text` — имя объекта и текст события на русском в нижнем регистре, ИИН, телефоны и e-mail в нём — маской.)
* `k.d.p.api.PasswordPolicy` (via `k.d.p.security.CommonPasswordPolicy` -- Правила пароля PLT-05 без требований к составу, как у NIST SP 800-63B: длина, список частых паролей, совпадение с контактами аккаунта. <ul> <li>длина — в символах Unicode, а не в UTF-16: эмодзи — один символ;</li> <li>список — {@value #COMMON_PASSWORDS}, 10 000 самых частых паролей из SecLists (MIT, атрибуция — рядом, в `common-passwords.NOTICE.txt`), сравнение без учёта регистра;</li> <li>телефон — по цифрам: +7 707 123 45 67, 87071234567 и 7071234567 для пароля — один номер;</li> <li>e-mail — целиком или часть до @, без учёта регистра.</li> </ul>)
* `k.d.p.identity.AccountSessions` (via `k.d.p.security.RedisAccountSessions` -- Активные сессии аккаунта по индексу Spring Session `FindByIndexNameSessionRepository`: имя в индексе — id аккаунта, его ставит вход (`k.d.p.security.SessionAccountSignIn`). Завершение необратимо: сначала отметка отзыва в Valkey (`k.d.p.security.SessionRevocations`), потом `deleteById` — сессия помечается истёкшей и убирается из индекса сразу, следующий запрос с её cookie — 401. Отметка нужна, потому что `deleteById` сессию не удаляет, а запрос этой сессии, который шёл в тот момент, в конце записал бы её обратно. Завершение всех ставит ещё и отметку аккаунта: она гасит и сессии, которых в индексе нет. Сессия текущего запроса завершается как выход, `HttpSession.invalidate()`: иначе конец запроса записал бы её обратно, а ответ не стёр бы cookie.)
* `k.d.p.identity.RateLimits` (via `k.d.p.security.RedisRateLimiter` -- Лимиты частоты в Valkey, общие для всех экземпляров приложения. Два вида: <ul> <li>частота — попытки входа с IP и общий API: Bucket4j, официальная интеграция `bucket4j-lettuce`, корзины через compare-and-swap, сглаженное пополнение `refillGreedy`: всплеск до лимита, потом ровный поток. Подключение — отдельное соединение Lettuce того же клиента, что у Spring Data Redis: адрес, пароль и TLS из `spring.data.redis.*`;</li> <li>не больше N событий за любой период — неверные попытки входа на логин и письма сброса пароля: скользящее окно, журнал времён событий в sorted set, Lua-скрипт через `StringRedisTemplate`. У Bucket4j корзины, а не журнал: `refillIntervally` считает окна от создания корзины, и на стыке двух окон проходило бы вдвое больше лимита. Набралось 5 неверных попыток за 15 минут — вход на логин закрыт на 15 минут от пятой, ключ блокировки хранит её конец.</li> </ul> 
+
Проверка входа занимает место в журнале логина атомарно, до проверки пароля: в журнале и неверные попытки, и те, что ещё идут. Поэтому одновременные попытки на один логин, с одного IP или с разных, не проходят проверку разом: пока нет успешного входа, пароль логина за любые 15 минут проверяется не больше 5 раз. 
+
Ключ — `dentify:rate:<лимит>:<SHA-256 значения>`: логин, e-mail, IP и id сессии в Valkey в открытом виде не лежат. Ключ живёт, пока нужен лимиту, дальше Valkey его удаляет. Время — часы приложения (`TimeMeter`): и у корзин Bucket4j, и в журналах.)
* `k.d.p.api.CurrentAccountProvider` (via `k.d.p.security.SecurityCurrentAccountProvider` -- Вошедший аккаунт — из контекста Spring Security: имя `Authentication` — id аккаунта, его ставит вход (`k.d.p.security.SessionAccountSignIn`). Без входа и в системной задаче — пусто. По нему аудит заполняет `created_by` и `updated_by`.)
* `k.d.p.api.CurrentPermissions` (via `k.d.p.security.SecurityCurrentPermissions` -- Права текущей работы — authorities контекста Spring Security: то же, что проверяет `hasAuthority` в `@PreAuthorize`. Без входа и в фоновой задаче прав нет.)
* `k.d.p.identity.AccountSignIn` (via `k.d.p.security.SessionAccountSignIn` -- Вход и выход в сессии Spring Session по рецепту Spring Security для своего эндпоинта входа: контекст с `Authentication` сохраняется в `SecurityContextRepository`, до этого — стратегия сессии, как у стандартных фильтров входа: смена id сессии и CSRF-токена. 
+
В контексте — `UsernamePasswordAuthenticationToken` с именем, равным id аккаунта, без пароля и без прав. Права по клинике в сессию не кладутся: сессия живёт до 30 дней, и права в ней пережили бы смену роли и смену клиники. Эффективные права считаются на запрос по клинике контекста и членству (docs/architecture.md, Права). По имени Spring Session ведёт индекс сессий аккаунта. В сессии только классы Spring и JDK, сессия не зависит от классов приложения. Клиент — IP и User-Agent — записывается при входе (`k.d.p.security.SessionClients`). Клиника прежнего входа снимается и с сессии, и с потока запроса: её выбирает вход после проверки членства. 
+
Срок сессии — `k.d.p.security.SessionLifetime`: без Запомнить — 12 часов бездействия, с Запомнить — 30 дней от входа, и cookie с тем же сроком. Срок от входа проверяет `k.d.p.security.SessionLifetimeFilter`. Выход необратим: сессия отзывается (`k.d.p.security.SessionRevocations`) до уничтожения.)
|Properties
|* `dentify.audit.default-period` -- `java.time.Duration`, default `30d`. Период ленты журнала, если начало не задано: последние 30 дней до конца периода или до сейчас. История одного объекта (фильтр по объекту) — за всё время.
* `dentify.audit.export-max-rows` -- `java.lang.Integer`, default `10000`. Предел строк выгрузки журнала: больше — 422, нужно сузить период или фильтры.
* `dentify.audit.partitions.cron` -- `java.lang.String`, default `0 17 3 * * *`. Когда проверять партиции: cron в UTC, по умолчанию раз в сутки ночью.
* `dentify.audit.partitions.months-ahead` -- `java.lang.Integer`, default `3`. На сколько месяцев вперёд держать партиции, от 1 до 24.
* `dentify.audit.search-max-period` -- `java.time.Duration`, default `366d`. Самый длинный период поиска по тексту: у поиска нет индекса, он просматривает все события периода.
* `dentify.audit.view-dedup-window` -- `java.time.Duration`, default `15m`. Окно просмотров: не больше одного события просмотра на аккаунт и объект за это время.
* `dentify.i18n.kk` -- `java.lang.Boolean`, default `false`. включён ли казахский (PLT-34): вместе со словарями `messages_kk`. Пока false — все ответы на русском, какой бы язык ни пришёл, а переключатель языка на фронте скрыт
* `dentify.security.content-security-policy` -- `java.lang.String`, default `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'`. Content-Security-Policy ответов бэкенда. Для страниц SPA тот же заголовок ставит Caddy. Скрипты — только со своего origin, без unsafe-inline; встраивание во фреймы запрещено.
* `dentify.security.geoip.database` -- `java.lang.String`. Путь к файлу базы в формате mmdb, например DB-IP IP to City Lite; относительный — от рабочего каталога. Не задан или файла нет — город сессий не определяется, приложение работает. База не коммитится, как её получить — backend/README.md. Строка, а не Path: конвертер Spring понял бы путь как ресурс и не принял бы ../ в начале.
* `dentify.security.hsts-max-age` -- `java.time.Duration`, default `365d`. Strict-Transport-Security: срок, в течение которого браузер ходит только по HTTPS.
* `dentify.security.password-hashing.concurrency` -- `java.lang.Integer`. Сколько хэшей пароля считается одновременно, остальные ждут. Не задано — по числу ядер процессора: хэш занимает ядро целиком, больше одновременных вычислений быстрее не станет. Память — 19 МиБ на каждое.
* `dentify.security.password-hashing.max-wait` -- `java.time.Duration`, default `3s`. Сколько запрос ждёт места для хэша; не дождался — 429 с Retry-After.
* `dentify.security.permissions-policy` -- `java.lang.String`, default `accelerometer=(), autoplay=(), camera=(), display-capture=(), geolocation=(), gyroscope=(), magnetometer=(), microphone=(), midi=(), payment=(), usb=()`. Permissions-Policy: возможности браузера, которые приложению не нужны, выключены.
* `dentify.security.rate-limit.api.capacity` -- `java.lang.Integer`, default `0`. сколько событий разрешено
* `dentify.security.rate-limit.api.period` -- `java.time.Duration`. за какой период
* `dentify.security.rate-limit.login-failures.capacity` -- `java.lang.Integer`, default `0`. сколько событий разрешено
* `dentify.security.rate-limit.login-failures.period` -- `java.time.Duration`. за какой период
* `dentify.security.rate-limit.login-ip.capacity` -- `java.lang.Integer`, default `0`. сколько событий разрешено
* `dentify.security.rate-limit.login-ip.period` -- `java.time.Duration`. за какой период
* `dentify.security.rate-limit.login-lock` -- `java.time.Duration`, default `15m`. Блокировка входа на логин после лимита неверных попыток, от последней из них.
* `dentify.security.rate-limit.password-reset.capacity` -- `java.lang.Integer`, default `0`. сколько событий разрешено
* `dentify.security.rate-limit.password-reset.period` -- `java.time.Duration`. за какой период
* `dentify.security.remember-me` -- `java.time.Duration`, default `30d`. Срок сессии и её cookie при входе с галочкой Запомнить — от входа, активность его не продлевает. Сервер гасит сессию по этому сроку сам (`k.d.p.security.SessionLifetimeFilter`), cookie получает тот же `Max-Age`.
* `dentify.security.session-max-age` -- `java.time.Duration`, default `30d`. Предельный срок сессии без Запомнить от входа, даже при непрерывной активности: кроме 12 часов бездействия (`server.servlet.session.timeout`). Не дольше, чем с Запомнить: украденная cookie не живёт бессрочно.
